### 1.1 Round-2 fixes applied in this pass (measured)

| Page | Fix | Root cause (measured) | Before → After |
|---|---|---|---|
| `/about/` + all pages | Metric-matched `Inter Fallback` `@font-face` (`src: local('Arial')`, `size-adjust: 107.12%`, `ascent-override: 90.44%`, `descent-override: 22.43%`, `line-gap-override: 0%`) injected into `--font-family` (`src/index.css`) | Google Fonts is loaded async (`media="print" onload`), so first paint used the fallback face and reflowed when Inter arrived. Lighthouse attributed the shift to `<img class="about-company-logo">` + “Web font loaded” | `/about/` **CLS 0.203 → 0.019** (mobile), **0.194 → 0.008** (desktop). Desktop Performance **89 → 97** |
| `/about/` | `.about-company-logo` now reserves its box: `width: 180px; height: 48px; aspect-ratio: 180/48` (mobile `143×38`) instead of `width: auto` | `width: auto` gave the logo 0 width until decode, pushing the founder section down | Removed the second CLS contributor (kept as belt-and-braces alongside the font fallback) |
| `/services/` mobile | Frame-sequence idle keyframe step on mobile raised **15 → 45** in `ServicesScrollAnimationSection.jsx` (+ same in the three app/section-3 sequences, `12 → 40` in `ScrollAnimationSection.jsx`) | 300-frame hero preloaded ~21 full-resolution JPGs (~290 KB each ≈ 6 MB) on cellular before the user scrolled | Services mobile payload **7,583 KB → 4,387 KB**, LCP **9.7 s → 4.7 s**, Performance **39 → 56** |

### 1.2 Known limitations (not fixed — do not read as solved)

- **`/download/` mobile is still bad and my frame throttle did not help it.** An A/B on the same build measured step 45 = 49 / 49 / 36 and step 15 = 52 / 44 (a single earlier run hit 69, which was an outlier). The change is kept because it objectively removes ~3.4 MB from the mobile load, but the score is dominated by **“Style & Layout” 6.3 s** of main-thread work and 2.6 s TBT — i.e. layout thrash in the two sticky canvas stages, not image bytes. `/download/` also loads **10 MB on desktop** (59 requests), the heaviest page on the site.
- **Font Awesome webfonts:** 147 KB `fa-solid-900.woff2` + 106 KB `fa-brands-400.woff2` from cdnjs remain render-blocking on every page.
- **Order page mobile LCP 8.3 s:** the frame-sequence hero is still the LCP element and the page ships 3,262 KB.
- **Accessibility is 94 site-wide** (measured in the first sweep, unchanged by these fixes): 48 contrast failures on home / 30 on order (`#0284c7` on white ≈ 3.9:1, below 4.5:1), `heading-order`, and `label-content-name-mismatch`.
- Home `/terms/` mobile CLS 0.067 — below the 0.1 “good” threshold but worth watching.

| Cause | Evidence | Impact |

## 2. Responsiveness

### Bugs found and fixed

| Page | Bug | Evidence | Fix |
|---|---|---|---|
| `/order/` | Order form panel **592 px wide on a 373 px viewport**; page scrolled sideways by 233 px | `document.documentElement.scrollWidth = 606` vs `clientWidth = 373` | `.order-container-grid` → `minmax(0, …)` tracks + `.order-container-grid > * { min-width: 0 }` (`src/index.css`) |
| `/` (≤380 px) | 3D carousel cards rotate outside their box → page scrolls horizontally by 44 px | `window.scrollTo(200,0)` returned `scrollX = 44` | `.slideshow-section { overflow-x: clip }` (`src/index.css`) |
| All pages | Any future transform/absolute overflow | — | `html, body { overflow-x: clip }` with `hidden` fallback (clip keeps `position: sticky` working) |
| All pages | Media could exceed container | — | `img, svg, video, iframe { max-width: 100% }` |

## 3. Competitor Gap Analysis (Pakistan + global benchmarks)

### What Pakistani competitors have that Zyphuel does not

| Feature | Competitor evidence | Zyphuel status | Priority |
|---|---|---|---|
| **Google Play listing with ratings** | FuelStation app: 5.0★ (12 reviews), 1K+ downloads | Direct APK only; Play badge shows “Launch Soon” | High — store listing is the strongest trust signal for a new app |
| **Promotional first-order offer** | FuelWala: 20% off convenience fee for 12 months (pre-launch signup) | No promo, no referral, no loyalty | High |
| **WhatsApp widget on every page** | fueldelivery.pk shows a WhatsApp chat widget site-wide | Float button exists only on `/contact/` | High |
| **Named team / real people** | FuelStation lists founder + 3 leads with roles | No team page; only founder paragraph on About | Medium |
| **Public fuel-price page** | fueldelivery.pk has “Fuel Prices in Pakistan” in nav | Price ticker on order page only; API fetch currently fails and still shows “Live” | High |
| **B2B / fleet portal** | EzFuels smart tanks (500/1,000/2,000 L) with auto-reorder and consumption monitoring; fueldelivery.pk is B2B-first | B2B only via “contact us” | Medium |
| **Subscription / scheduled refuel** | CAFU Go: AED 39/month plan (global benchmark); EzFuels auto-reorder | None | Medium |
| **Loyalty / referral rewards** | CAFU Rewards points → wallet credit (global benchmark) | None | Medium (no Pakistani competitor offers it — differentiator) |
| **Live order tracking + ETA on web** | FuelStation/EzFuels claim tracking; Zyphuel claims live GPS only in the APK | Web has no tracking/ETA view | Medium |
| **Verifiable safety proof** | RevUp (ADR permit, licensed), Booster (DOT/EPA/NFPA), FuelStation (physical Johar Town address, named team) | Claims OGRA/HAZMAT compliance; no certificate/insurance document shown | High |

### Where Zyphuel already leads locally
- **Price transparency**: published delivery-fee bands (Rs 300 / Rs 320–400) and COD limits — competitors hide fees or show none.
- **Payment breadth**: COD + JazzCash + Easypaisa + NayaPay + SadaPay + Raast + Mashreq.
- **Service detail**: 5–15 L limits, 45-minute SLA, 50 m hoses, 0.01 L metering, Urdu support claim.
- **SEO infrastructure**: 17 prerendered routes, structured data, sitemap, IndexNow, 100 SEO score on the order page.

### Gaps that hurt conversion most (ranked)
1. **No social proof anywhere** — zero reviews/testimonials on site, no Play Store rating. Every global benchmark (CAFU 4.6★/11k, EzFill 4.8★/449) leads with ratings.
2. **No offer/incentive** for a first order (FuelWala has one).
3. **WhatsApp only on one page** — the main Pakistani conversion channel is under-used.
4. **Order flow dead 10 PM–8 AM** with no pre-booking and no WhatsApp CTA in the cutoff card.
5. **“Live” badge shown even when the price API fails** — trust risk.
6. **No team/real-people page** — a stranger arriving at your gate needs a face and a name.
7. **Email required in the order form** — unnecessary friction for COD fuel.
8. **No analytics** — no visibility into where users drop.

## 4. Recommended Next Steps (impact order)

1. **`/download/` mobile (34):** drop the second frame sequence on mobile or replace both with a single compressed video / static poster. Target the 6.3 s Style & Layout, not image bytes — the byte reduction alone did not move the score.
2. **Frame-sequence heroes site-wide:** serve 960 px-wide mobile frames (or `<video>` with `preload="none"` + poster) instead of 2560 px JPGs; keeps `/services/` and `/order/` payloads under 1 MB.
3. **Self-host/subset Font Awesome**, or replace with inline SVG (saves 253 KB and two blocking requests).
4. **Fix color contrast**: darken `#0284c7` to at least 4.5:1 on white (`#0369a1` ≈ 4.5:1) for normal-size text — 48 nodes on home.
5. **Fix heading order and label/name mismatch** (accessibility 94 → 100).
6. **Add a reviews/ratings section** with real Google reviews + Play Store listing.
7. **Add a site-wide WhatsApp float button.**
8. **Add first-order incentive + referral code.**
9. **Fix the price API fallback:** hide the “Live” badge when `isLive === false`.
10. **Move the h1 + primary CTA above the cinematic animation** (order page mobile LCP 8.3 s).
